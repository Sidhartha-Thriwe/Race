feat(race): backend for skill 1 — identity resolution via Claude Agent Skills

Adds the host half of the race_fetch_vendor contract so skill 1 can run from
the app. The sandbox that runs Agent Skills has no network; the skill asks the
host to fetch and does everything else itself. The host holds the keys, makes
one HTTPS call, and returns the payload unmodified — every guard and every
piece of RACE judgement stays in the skill, where it is tested.

  server/race/vendors.ts  three vendors, monthly caps, item counts on the raw
                          shape (a 200 with an empty body is the failure that
                          looks like success)
  server/race/store.ts    run index, per-run artifacts, subject ids from P-20,
                          spend ledger. Credentials are scrubbed before disk
                          even when raw retention is on.
  server/race/claude.ts   the agent loop: container.skills + code_execution +
                          race_fetch_vendor in one request, container reused
                          across turns. Refuses to start unpinned.
  server/race/routes.ts   /api/race/{status,run,runs,runs/:id,subjects},
                          behind x-race-token, required in production.

POST /run returns 202 with a runId and works in the background; a three-vendor
run outlasts any sane HTTP timeout. It requires a consentBasis string, stored
with the run — not enforced, but an unattributable run is one nobody can answer
for later. The run index stores a hash of the address rather than the address,
so the operational view is readable without being a list of people.

Run records are on the container filesystem, which is ephemeral on Cloud Run.
Set RACE_DATA_DIR to a mounted volume before treating them as an audit trail.
